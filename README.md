# intraHouse Git Sync

Плагин для intraHouse 5. Отправляет правки в приватный Git-репозиторий проекта, получает изменения после слияния PR и создаёт локальные снимки. В Git хранятся заглушки, рабочие значения берутся из локального `.env`.

| Команда | Действие |
|---|---|
| `refresh` | Проверить состояние рабочей копии и GitHub |
| `sync` | Проверить секреты в индексе, сохранить правки и отправить коммит |
| `deploy` | Сделать снимок, применить fast-forward и запустить intraHouse |
| `rollback` | Сделать страховочный снимок и восстановить файлы из снимка перед последним развёртыванием |
| `backup` | Создать снимок проекта и снова запустить intraHouse |

Если ветки разошлись после локального коммита, `sync` отправляет его в ветку `ui/…`. Влейте её в целевую ветку через merge-коммит, чтобы Git сохранил локальный коммит в истории. После этого можно нажать «Получить». Откат возвращает файлы, сохраняя текущий Git HEAD. Восстановленные файлы будут видны как локальные изменения.

## Установка и миграция

На Linux требуются Git, Python 3, GNU tar, flock и systemd. Установите плагин целиком, включая `ops/`. Путь установленного плагина должен быть постоянным. Сделайте штатную резервную копию intraHouse перед переходом.

На сервере выполните от владельца проекта до получения коммита, удаляющего старый каталог `tools/`:

```sh
sh /путь/к/plugins/gitsync/ops/install.sh /путь/к/проекту
```

Установщик переносит копии прежних `tools/ihsecrets.json` и `tools/ih.conf` в `.git/gitsync/`, перенастраивает Git-фильтр и заменяет старую символьную ссылку на хук плагина. Проверьте маскирование командой `python3 /путь/к/plugins/gitsync/ops/ihsecrets.py check` из корня проекта. Отправляйте изменения из intraHouse кнопкой `sync`, которая проверяет итоговый индекс. Установленный хук дополнительно запускает Gitleaks, если он доступен. После миграции храните копии приватных правил, настроек и `.env` в защищённом хранилище.

Для нового проекта передайте установщику пути к своим правилам и конфигурации вторым и третьим аргументами. Примеры находятся в `ops/`. Укажите правила для всех секретов, создайте локальный `.env` с правами 600, проверьте три атрибута `filter=ihsecrets`. Команда `ihsecrets.py extract` заполняет `.env` на основе правил и текущих данных проекта.

Для экземпляра плагина задайте каталог проекта, ветку и remote. Настройте runner `systemd-run --collect --unit=ih-gitsync-%ts` и команды `IH_STOP` / `IH_START` в `.git/gitsync/ih.conf` под права вашей службы. Служба обслуживания должна иметь доступ к Git, проекту, SSH-ключу и каталогу снимков от своего имени. Для существующего набора каналов добавьте канал `backup` с правом записи или вызовите `sh /путь/к/plugins/gitsync/ops/project.sh backup /путь/к/проекту origin main` от пользователя службы обслуживания.

Резервная копия создаётся после остановки intraHouse, поэтому на время этой операции будет пауза в работе. Архив `tar.gz` включает рабочие файлы, локальный `.env` и `private/`. Каталоги `hist/`, `logdb/` и `operative/` исключаются из снимка. При откате они остаются на месте. Архив сохраняется вне проекта с правами 600. По умолчанию хранятся 20 последних снимков и снимок, необходимый для отката. Для `IHSECRETS_ENV` вне проекта храните отдельную копию этого файла. Команды плагина отражают результат через канал `result`. Для диагностики используйте журнал transient unit `ih-gitsync-*`.

Публичный API плагинов intraHouse не описывает вызов штатного архивирования из веб-интерфейса. Плагин использует собственный архив файлов. Штатный ZIP можно по-прежнему создать в интерфейсе intraHouse.

## Тип устройства, диалог и иконки

В каталоге `extras` поставляются тип **GitSync · Git проекта**, диалог и gitsync-project.svg.
Установщик работает с файловым проектом intraHouse v5. Выполняйте его от имени владельца проекта при остановленном intraHouse, предварительно сохранив резервную копию проекта.

1. Добавьте тип и иконки командой `node extras/install.js /путь/к/проекту`.
2. Запустите intraHouse. Создайте устройство этого типа в Project Manager и привяжите набор каналов плагина. У каналов из нового набора уже указаны имена целевых свойств. Запишите внутренний ID устройства, например `d0123`.
3. Остановите intraHouse, затем выполните `node extras/install.js /путь/к/проекту d0123`. Эта команда добавит диалог для указанного устройства и выведет его ID.
4. Запустите intraHouse. В редакторе плитки выберите иконку из ресурсов проекта и назначьте действие **Показать диалог**. Передайте ID устройства в клиентскую переменную `dev_id` (стандартная переменная «ID устройства»).

Импорт ZIP устанавливает плагин. Ресурсы добавляются отдельно в выбранный проект. Для каждого устройства можно установить свой экземпляр диалога. Установщик сохраняет существующие записи и прекращает работу при конфликте с уже существующим файлом.
