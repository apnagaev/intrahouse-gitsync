# intraHouse Git Sync (gitsync)

Плагин для **intraHouse 5**, который показывает состояние Git-репозитория проекта и позволяет вручную отправлять изменения, получать утверждённые коммиты и запускать откат.

> **Статус:** версия 5.0.2, исходники для самостоятельной установки. Не проверено на работающем сервере. **Не запускайте Deploy/Rollback на действующей системе без предварительного теста на копии проекта.**

## Возможности

- `refresh`: проверить Git (fetch) без изменения рабочих файлов.
- `sync`: проверить локальные изменения, создать коммит и отправить его в удалённый репозиторий.
- `deploy`: запустить внешний `tools/ih-deploy.sh` через `systemd-run` для развёртывания.
- `rollback`: запустить внешний `tools/ih-rollback.sh --latest`.
- Показать состояние, число локальных изменений, отставание/опережение, последние коммиты и результат операции.

Периодическая проверка выполняет только `git fetch`. Автоматического развёртывания по расписанию нет.

## Требования

1. Работающий **intraHouse 5** с поддержкой пользовательских плагинов.
2. Linux-сервер с `git`, `python3` и `systemd-run`.
3. Каталог проекта intraHouse уже инициализирован как Git working tree, настроены `origin` и ветка (обычно `main`).
4. Пользователь, под которым запускается плагин, имеет права на каталог проекта и доступ к Git remote.
5. В каталоге **самого проекта** должны быть отдельно установлены и проверены:
   - `tools/ihsecrets.py` и его конфигурация/секреты для команды `check`;
   - `tools/ih-deploy.sh`;
   - `tools/ih-rollback.sh`;
   - связанные с ними настройки, фильтры, backup-скрипты и команды остановки/запуска intraHouse.

**Важно:** внешние скрипты не входят в этот репозиторий. Плагин не является автономным механизмом резервного копирования или безопасного развёртывания.

## Установка

1. Скачайте исходники репозитория или клонируйте его:
   ```sh
   git clone https://github.com/apnagaev/intrahouse-gitsync.git
   ```
2. Разместите содержимое репозитория в папке `gitsync` внутри каталога пользовательских плагинов intraHouse (рядом с другими плагинами). Сохраните `app.js`, `index.js`, `manifest.json`, `gitsync.ih`, `package.json` и папку `v5/`.
3. Перезапустите intraHouse или выполните предусмотренную вашей установкой процедуру обнаружения новых плагинов.
4. Добавьте экземпляр `gitsync` через интерфейс управления плагинами.

### Настройка

| Параметр | Описание | Пример |
| --- | --- | --- |
| `projectdir` | Абсолютный путь к Git-каталогу проекта intraHouse | `/srv/intrahouse/project` |
| `branch` | Рабочая ветка | `main` |
| `remote` | Git remote | `origin` |
| `fetchmin` | Интервал проверки в минутах, `0` — без автоматической проверки | `15` |
| `sshkey` | Путь к SSH-ключу, если используется отдельный ключ | `/home/ih/.ssh/deploy_key` |
| `runner` | Команда запуска вне процесса intraHouse | `systemd-run --collect --unit=ih-gitsync-%ts` |

### Доступ к GitHub

Для приватного репозитория проекта создайте **отдельный** SSH deploy key и добавьте его в **репозиторий проекта**, а не в этот публичный репозиторий. Для отправки изменений ключу необходим write access. Проверьте Git-доступ под тем же пользователем, что запускает intraHouse:

```sh
cd /srv/intrahouse/project
git remote -v
git fetch origin main
git status
```

Храните закрытый ключ вне Git. Не публикуйте `.env`, токены и конфигурацию дома.

### Каналы

Каналы чтения: `status`, `uncommitted`, `behind`, `ahead`, `local`, `remote`, `result`, `busy`.

Каналы команд (запись значения `1`): `refresh`, `sync`, `deploy`, `rollback`. После выполнения плагин сбрасывает значение команды в `0`.

Создайте набор каналов через меню плагина или вручную. Для кнопок на панели intraHouse свяжите действия с соответствующими каналами. Дополнительный пакет типа устройства в поставку не включён.

## Как использовать

1. Нажмите **Обновить** (`refresh`) и проверьте значения `behind` и `uncommitted`.
2. После изменений через интерфейс intraHouse нажмите **Отправить в Git** (`sync`). Убедитесь, что в удалённом репозитории появились ожидаемые коммиты.
3. Изменения, подготовленные через Pull Request, сначала проверьте и объедините в целевую ветку.
4. Перед **Получить и развернуть** (`deploy`) убедитесь, что внешние скрипты работают и есть проверенная резервная копия.
5. **Откат** (`rollback`) применяйте только после проверки процедуры восстановления.

## Безопасность и известные ограничения

- Проверка `ihsecrets check` зависит от внешней конфигурации и **не гарантирует** обнаружения всех секретов. Используйте защиту Git index/хуки и независимое сканирование.
- При ошибке `git push` реализация может попытаться отправить коммит в ветку `ui/...` даже при проблемах с сетью или правами.
- Состояние `busy` отражает запуск команды, а не весь жизненный цикл внешнего развёртывания.
- Валидация `.db` проверяет JSON-строки, но не защищает от конкурентной записи.
- Фактические последствия Deploy/Rollback определяются внешними скриптами; их нужно отдельно аудировать.
- Плагин использует локальные команды с правами пользователя intraHouse: не предоставляйте управление командами недоверенным пользователям.
